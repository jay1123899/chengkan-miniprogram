# 图片放置说明

把拍好的照片放进这个目录，然后在 `data/` 里的数据文件中填写路径即可。

> **⚠️ 当前目录里的 15 张 jpg 是程序生成的意象图，不是实景照片。**
> 它们由 `D:\n\gen_images.py` 绘制（马头墙剪影 + 青灰渐变 + 柔光），用途是在还没有照片时先把页面撑起来，**不涉及任何版权问题**。
> **建议尽快用自己的照片替换** —— 文件名保持一致，直接覆盖即可，代码一行都不用改。
> 替换成实景照片后，记得把"关于"页里的图片说明改回：`页面图片为景点实景，实际景观受季节与天气影响会有差异。`

## 一、命名建议

| 用途 | 文件名 | 数量 | 建议尺寸 |
| --- | --- | --- | --- |
| 首页轮播图 | `banner-1.jpg` ~ `banner-5.jpg` | 5 张 | 750 × 480 px（25:16） |
| 景点缩略图 | `<景点id>.jpg`，如 `baolunge.jpg` | 每景点 1 张 | 440 × 400 px |
| 景点详情图集 | `<景点id>-1.jpg`、`<景点id>-2.jpg` … | 每景点 1–3 张 | 长边 1200 px 以内，**竖图横图都行** |

景点 id 见 `data/spots.js`：`baolunge`、`changchunshe`、`yudeng`、`yongxinghu`、`gucunluo`

## 二、怎么填进代码

**轮播图** → `data/banners.js`
```js
{
  id: 'b1',
  spotId: 'yongxinghu',
  title: '呈坎古村',
  subtitle: '徽州古村落 · 水圳穿村',
  image: '/images/banner-1.jpg',   // ← 填这里
  bg: 'linear-gradient(135deg, #46605f, #7a9598)'
}
```

**景点图片** → `data/spots.js`
```js
{
  id: 'baolunge',
  image: '/images/baolunge.jpg',                        // ← 列表缩略图
  images: ['/images/baolunge-1.jpg', '/images/baolunge-2.jpg'],  // ← 详情页图集
  ...
}
```

留空字符串 `''` 或空数组 `[]` 时，页面会自动显示渐变占位块，**不会出现破图**，可以先把文案写完再补图片。

## 三、⚠️ 必须知道的体积限制

微信小程序**主包上限 2MB**，图片放在本地会占用包体。

**实测数据**：本项目代码与配置合计约 **41 KB**（31 个文件，未压缩；README、docs 等文档已通过 `packOptions.ignore` 排除，不计入）。也就是说**留给图片的预算大约是 1.9 MB**。

| 图片数量 | 每张 300KB | 每张 100KB | 每张 60KB |
| --- | --- | --- | --- |
| 25 张（5 轮播 + 5 缩略图 + 15 景点图） | 7.5 MB ❌ 超限，传不上去 | 2.5 MB ❌ 超限 | 1.5 MB ⚠️ 可用但偏紧 |
| 15 张（5 轮播 + 5 缩略图 + 5 景点图） | 4.5 MB ❌ 超限 | 1.5 MB ✅ 可以 | 0.9 MB ✅ 宽松 |

**结论**：全部照片放本地的话，每张必须压到 **60KB 以下**才安全。想省心就用图床 —— 而且就算没超限，图片越大首次打开越慢，上传体积和加载速度是两件事。

两个可行方案：

1. **压缩后放本地**（简单，但有上限）
   用微信开发者工具的图片压缩、或 TinyPNG 之类工具，把每张压到 **60–100KB**，总张数控制在 10 张以内。
   风格上尽量用横图，避免一张图占满包体。

2. **放网络图床**（推荐，包体零占用）
   把图片传到任意图床 / 对象存储（如微信云开发的云存储、阿里云 OSS、七牛等），拿到 `https://` 开头的地址直接填：
   ```js
   image: 'https://your-cdn.example.com/baolunge-1.jpg',
   images: ['https://your-cdn.example.com/baolunge-1.jpg', '...']
   ```
   `image` 组件加载网络图片**不需要**在后台配置域名白名单（这点和 `wx.request` 不同），可以直接用。

## 用图床放照片（推荐）

图片不一定要放在本地。`data/` 里的 `image` 与 `images` 字段**既支持本地路径，也支持完整网址**：

```js
image: '/images/baolunge-1.jpg',                                  // 本地图片
image: 'https://your-cdn.example.com/baolunge-1.jpg',             // 图床直链
images: ['https://your-cdn.example.com/a.jpg', 'https://.../b.jpg'],
```

用图床的好处：**小程序包体零占用**，主包永远轻，加载也不占用用户下载流量之外的额度。

**关键点**：`<image>` 组件加载外链图片**不需要**在 mp 后台配置服务器域名（只有 `wx.request`、`wx.downloadFile`、`wx.uploadFile`、`wx.connectSocket` 需要）。所以图床地址填进去就能用。

**选图床要注意的四件事**：

| 注意点 | 说明 |
| --- | --- |
| 必须 https | 小程序不允许 http 图片 |
| 稳定性 | 免费图床可能限流、跑路、清理旧图。图片一旦失效，对应位置会退回渐变占位块（项目已做加载失败回退，不会出现空白或破图） |
| 防盗链 | 部分图床开启防盗链后，在小程序里会加载失败 |
| 访问速度 | 国外图床在国内访问慢，建议用国内节点 |

**推荐顺序**：微信云开发「云存储」（同生态、有免费额度、最稳）→ 国内云厂商对象存储（阿里云 OSS / 腾讯云 COS）→ 免费图床（省事但有失效风险）。

**怎么批量填地址**：在项目根目录（`D:\n`）编辑 `image_urls.txt`，把每张图的直链填在等号右边，然后运行：

```
python set_image_urls.py
```

脚本会自动把地址写进 `data/banners.js` 和 `data/spots.js`。没填的行保持原样 —— 也就是说**本地图片和图床地址可以混用**：常用的几张放本地，其余走图床。


## 四、拍摄与选图建议

- **轮播图**：选横幅构图、主体明确的照片，避免画面太杂；五张之间风格尽量统一（都是白天、或都是阴天）
- **景点图**：每个景点至少一张"整体外观"+ 一到两张"局部细节"，详情页图集按这个顺序排
- **不要放人脸清晰可辨的路人**，涉及到就裁掉或换一张
- **不要放带定位信息、车牌、门牌号的照片**，尤其是你自己家门牌
- 图片色调统一一些，整体观感会明显提升
