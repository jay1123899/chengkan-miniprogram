# 呈坎小程序 · 演示录屏脚本

**目的**：面试官不会为了看你的小程序去加体验成员、扫码、折腾授权。一段 60–90 秒的录屏，是唯一"点开就能看"的证明。

---

## 一、录制前准备（5 分钟）

| 项目 | 要求 |
| --- | --- |
| 小程序状态 | 先用开发者工具导入项目、确认能跑；或用手机预览 |
| 手机状态 | 开勿扰模式，清掉通知栏，电量 > 50% |
| 微信 | 退出其他聊天窗口，避免弹出私人消息 |
| 隐私 | **录屏不要出现手机号、聊天记录、别人的头像昵称**；小程序内已无个人信息，但状态栏和通知要清干净 |
| 分辨率 | 1080p，竖屏录制 |
| 时长 | 目标 60–90 秒，超过 2 分钟面试官不会看完 |
| 音频 | 建议加口播；不方便就用剪映加字幕 |
| 保存 | 传微信收藏 + 网盘，准备好一个能直接发出的链接 |

## 二、分镜脚本（照着做，一遍能过）

| 时间 | 操作 | 画面要点 | 口播（照读也可以） |
| --- | --- | --- | --- |
| 0–10s | 打开小程序，停在**首页** | 顶部轮播自动播放，5 张图依次切换 | "这是我做的呈坎旅游宣传小程序，首页是五张轮播图和特色推荐。" |
| 10–20s | 手指左右滑动轮播 | 轮播跟手切换，指示点变化 | "轮播可以手动滑动，每张对应一个景点，点进去就是详情。" |
| 20–32s | 点击第二轮播（宝纶阁） | 进入详情页，顶部图片区 | "点进来是景点详情，顶部是图片区。" |
| 32–50s | 在详情页向下滚动 | 看点 → 景点介绍 → 游览提示 → 位置信息 | "详情页有看点、详细介绍和游览提示，提示里会写清楚光线、人流这些实际问题。" |
| 50–62s | 点击图片放大，左右滑动 | 全屏图片预览 | "图片可以点开放大，多张的话能左右滑动。" |
| 62–72s | 返回详情页，点"收藏" | 提示"已收藏"，按钮变化 | "收藏用的是本地缓存，不需要登录。" |
| 72–84s | 切到**景点** tab，搜索"彩绘"，再切分类 | 搜索结果 + 分类高亮 | "景点页支持关键词搜索和分类筛选，名称、标签、介绍内容都会参与匹配。" |
| 84–90s | 切到**收藏** tab 收尾 | 收藏列表 | "收藏页能看到收藏过的景点。以上就是全部功能。" |

> 时间紧就砍掉 72–84s 的搜索演示，保留：轮播 → 详情 → 图片放大 → 收藏 → 收藏页。

## 三、录制技巧

1. **提前想好手指路线**，别在录的时候犹豫找按钮 —— 停顿最显生硬。
2. **一次不成就重录**，控制在 3 遍以内。
3. **口播卡壳就改字幕**：录静音视频，用剪映加文字，效果一样好。
4. **结尾停在收藏页或关于页**，不要停在加载中或空白页。
5. 录完检查一遍有没有露出不该露的信息。

## 五、演示之外，务必准备这三个问题的答案

1. **"收藏功能怎么实现的？"**
   → 用 `wx.setStorageSync` 把收藏的景点 id 存成数组放在本地缓存，详情页和列表页读同一份缓存保证状态一致。局限是只在当前设备生效，换手机不同步。

2. **"搜索是怎么做的？"**
   → 先把景点数组按分类过滤，再用关键词去匹配名称、简介、标签、看点和正文，匹配到就留下，最后重新渲染列表。数据量小所以没用分词，直接 `indexOf` 判断。

3. **"遇到过什么问题，怎么解决的？"**
   → 提前想一个真实的。**没有真事就说局限，不要说假事**：这个项目数据是写在本地文件里的，没有后端，如果景点多了应该改成接口请求 + 分页加载；图片如果都放本地会撑爆小程序 2MB 的主包限制，所以要么压缩要么放到图床。
